# Talwacht Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser co-op siege-defence game for two phones: build and entrench a castle at the back of a natural valley, hold 25–30 escalating, adaptive waves that come only from the front.

**Architecture:** New npm workspaces `talwacht/shared` (data, terrain, grid, autotile, wire codec), `talwacht/server` (authoritative 20 Hz simulation + WebSocket rooms), `talwacht/client` (Three.js + Vite). Burgwacht stays untouched; reusable client/server modules (viewport, post-processing, baked-unit loader, asset loader, audio, connection, room/server) are **copied and adapted** instead of extracted into `common/` — deviation from spec §13, chosen so Burgwacht cannot break. Shared 3D assets are served from `client/public/assets` (Vite `publicDir`).

**Tech Stack:** TypeScript, Three.js 0.186, Vite 8, Node 22 + `ws`, Vitest 5, Playwright (pre-installed Chromium) for e2e and baking.

**Spec:** `docs/superpowers/specs/2026-11-06-talwacht-design.md`

## Global Constraints

- All player-facing text German, "du"-form, plural "ihr" for both players.
- Attacks only from the front (low map y). No climbers, no attacks from behind or over cliffs.
- Max army 100 per player; tower garrisons never count towards it.
- Round 30–60 min: Normal 25 waves, Easy 25 waves, Hard 30 waves.
- Grid cell 4 m for everything (deviation: spec's 2-m trap sub-cells dropped; one trap per cell).
- Crenel slots: 2 per wall cell (one per 2 m), +2 per tower.
- Server authoritative; clients send commands only.
- Low-poly CC0 assets only (KayKit, Kenney, Quaternius) plus procedural geometry in one palette.
- Target ≥ 30 FPS with 400 figures on iPhone 12 class; `?q=low` quality switch.
- Phone landscape 667×375 … 932×430 must fit all HUD controls (touch targets ≥ 40 px).
- Saves survive a sleeping free-tier server (stored on both clients).

## Review Focus

1. Players wall off the whole valley → enemies must still reach the keep by breaking the cheapest wall/gate (flowfield treats structures as costly, never infinite). Test in Task 6.
2. Ranged squad larger than the tapped wall segment → overflow to neighbouring connected wall/tower cells, never two archers on one slot, never on a different wall component. Test in Task 7.
3. Wall cell destroyed under defenders → they drop to the ground cell inside and re-request slots. Test in Task 7.
4. Save from an older build or a corrupt/oversized save uploaded → rejected with a German error, room not created. Test in Task 13.
5. One player disconnects mid-wave → game pauses, rejoin with same code restores seat (copied Burgwacht behaviour). Test in Task 13.

### Task 9: Siege and formations

**Files:** Create `talwacht/server/src/sim/siege.ts`, test `siege.test.ts`. **Produces:** `spawnTestudo(s, lane, n) -> formationId`, `siegeTick(s, dt)`, `isShielded(s, unit, from) -> boolean`.

- Testudo: `n` e_shield in rect around a ram (cols 4), moves as one at ram speed, keeps slots; while intact (≥ 60 % alive, not broken): ranged pierce/bolt/arrow from front or above −85 %; ballista, fire, stone full; melee from flank (> 60° off facing) ×1.6 (halberdier ×2). Broken by catapult/rockslide/powder hit for 6 s (members scatter 2 m, then re-form). At gate: ram hits gate, shields hold.
- Ladders: team reaches wall cell, plants ladder (4 s), climbs one per 1.2 s to the nearest slots, fights on wall (`z>0`), then descends inward. Defenders adjacent damage ladder.
- Siege tower: path cost ignores ladders, blocked by moat; docks, unloads 12 over 10 s.
